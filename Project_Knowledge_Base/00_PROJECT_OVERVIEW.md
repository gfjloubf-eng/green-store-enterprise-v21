# Green Store Enterprise — Project Overview

## اسم المشروع
**Green Store Enterprise**

## وصف المشروع
منصة تجارة إلكترونية (واجهة طلب/سلة + إدارة منتجات/طلبات) مع فصل طبقات أساسي داخل PHP.

## فكرة المشروع
تجهيز متجر إلكتروني مع تدفق طلب واضح:
1) استقبال بيانات الطلب من الـ frontend (JSON).
2) التحقق من صحة البيانات عبر طبقة Validation.
3) التحقق من وجود المنتجات في قاعدة البيانات.
4) حفظ الطلب ضمن جدول `orders` مع تخزين منتجات الطلب بصيغة JSON.
5) إرجاع استجابة موحدة بصيغة JSON.

## أهداف المشروع
- تحسين موثوقية معالجة الطلبات (Validation + رسائل الأخطاء).
- تقليل الـ duplication داخل endpoints.
- جعل الكود أكثر قابلية للصيانة عبر تنظيف بنيوي تدريجي.
- الحفاظ على **Backward Compatibility** للـ JSON structure ورسائل النظام.

## الجمهور المستهدف
- مطورو Backend/PHP في فريق Green Store.
- مطوري Frontend المتكاملين مع API الخاص بالطلبات.
- أي نموذج ذكاء اصطناعي يعمل على المشروع لاحقًا (يحتاج مرجع Markdown كامل).

## المشاكل التي يحلها
- أخطاء/اختلافات في رسائل Validation عند تكرار المنطق.
- تدهور قابلية الصيانة بسبب كود legacy.
- اختلافات محتملة في structure الاستجابة (success/error/validationError).

## حالة المشروع الحالية
- يوجد بنية PHP مع طبقات `App\Core\Validation` و `App\Core\Response`.
- endpoint `save_order.php` مسؤول عن استلام الطلب وحفظه.
- هناك Technical Debt في التكامل بين Validation والتحققات اليدوية داخل `save_order.php`.

## نسبة الإنجاز
غير محدد رقميًا—التركيز الحالي على **الـ Maintenance & Refactoring Execution** وليس إضافة ميزات.
